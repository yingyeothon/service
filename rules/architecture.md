# Architecture

- Layout: `packages/*` (shared libs: core, redis, jwt, http, ws, console-db), `services/{auth,console,topic,match,state}` (one Serverless stack each), `apps/console-web` (React+Vite SPA), `cli/` (Go), `scripts/`, `examples/sample-dungeon` (tslib integration).
- Console SPA (`apps/console-web`) is mounted at `/ui/` on the console API host: the session cookie is `__Host-` (same host required) and the API owns the root paths (`/events`, `/channels`), so SPA routes must not collide. `WEB_URL` (login landing) is `https://{domain}/ui`; `next` is the router-relative path. Keep `vite base`, `BrowserRouter basename`, `WEB_URL` and the CloudFront `/ui/*` behavior (todo/07) in sync. UI stack (2026-08-24): Mantine 8 + `@tabler/icons-react` (compact light-only theme in `src/theme.ts`, AppShell layout) and TanStack Query 5 via `src/lib/query.ts` `useApiQuery` — `staleTime: 0` keeps the old refetch-on-mount semantics, `set` writes through to the cache; the auth provider calls `queryClient.clear()` on logout/401 so cached rows never outlive a session. `src/navigation.ts` NAV_ITEMS is the single source for both the side menu and route guards (`App.tsx` `navMinRole`). The installer download (`GET /catalog/installer/downloads`, member-only) is a first-class SPA surface (2026-08-27): a `/installer` nav item plus a download card at the top of Home — a link buried under the feature list was reported as "not exposed", so the latest build is always a button on the first screen after login, never only a small anchor. Trap found there: with `staleTime: 0`, a page that early-returns a spinner while `loading` and mounts a child sharing the same query key only after that spinner is gone will loop forever on a query error (child mounts → new observer refetches → page shows spinner → child unmounts → error → …); mount such children only once `data` exists, and cover the error path in a test — no SPA test rejected a query before 2026-08-27.
- Services depend only on `packages/*`; never import another service's `src`. Cross-service data goes through the console MySQL database (SELECT-only accounts for auth/topic/match; `state` additionally writes `state_docs` and nothing else) or Redis.
- The console stack owns the schema and every migration, and is the only writer of every table **but `state_docs`** (`state`, 2026-08-26). auth/topic/match/state read channel config through the same `@yyt/console-db` repository with their own account; rows with secrets (auth channels) are never cached in Redis.
- The `state` stack (`services/state`, `doc{-dev}.yyt.life`) serves the **doc** storage shape and nothing else. It is the pattern to copy for a stack that only needs MySQL: no Redis client, no `REDIS_*` env, no schema of its own, one route table. Its document namespace hangs off the **auth** channel, because `ownerId` is `deriveUserId(authChannelId, …)` and means nothing outside it — which is also why its routes need no channel segment and its apiKey carries the channel id instead (`newDocKey`/`docKeyChannelId` in `@yyt/core`).
- Follow tslib API conventions (`~/git/yyt.life/tslib/CONVENTIONS.md`): `create*` factories returning interfaces, no exported classes, options object when >2 params or any optional param, no `process.env`/`console.*` inside `packages/*` (handlers read env once and pass options), `logger?: Logger`.
- Keep the JWT claim contract (`iss=yyt-auth/{channelId}`, `aud`, `sub=userId`, `exp`) identical to `docs/auth-game-contract.md` so tslib's `createJwtRequestAuthorizer` verifies our tokens unchanged.
- Team → Project → Resource (2026-08-26, `docs/decisions.md` _Teams and projects_): every channel/app/bundle row carries `team_id` + `project_id` (`NOT NULL` since `m0008_team_project_contract`), and authorization is team membership read through `TeamDb` (`@yyt/console-db` `src/team.ts`). `owner_id` survives only as `createdBy` for display. The rework landed in stage-sized commits (`todo/17-team-project.md` §6; `orgproj` merged into `main` 2026-08-26). Clients address resources by id or by team-unique name; the SPA resolves names through the list pages, the CLI through `internal/cmd/context.go` (flag > env > `.yyt.json` > profile > auto-select for reads).
- Never add new persistence technologies (DynamoDB, RDS) — the decision is self-hosted MariaDB + Redis (`docs/decisions.md`). Reopen `docs/decisions.md` if that proves insufficient.
- Do not port legacy repos' build layers (node8–14, webpack); only port algorithms (`lobby-api/src/match`) with fresh tests.
- Storage packages expose a repository/`Kv` interface plus an in-memory fake (`createMemoryConsoleDb`, `createMemoryKv`); services and tests depend on the interface, and only `handler.ts` constructs the real driver (`createMysqlDb`/`createRedisKv` from `*OptionsFromEnv()`), once per container.
- Packages are built with `tsc -p tsconfig.build.json` into `dist/` (ESM only, `exports["."]`), and services bundle them with esbuild; `pnpm -r build` must run before a service bundle or typecheck. `package.json` `main/types` point to `dist` — no `src` fallback.
- Handlers return plain objects (→ 200 JSON), `undefined` (→ 204) or an `HttpResult`; throw `AppError` for every client-visible failure so the router maps status/code uniformly.
- Route tables: wrap routes in `defineRoute({...})` from `@yyt/http` so `body`/`query` zod inference flows into the handler; the table type is `AnyRoute[]`. Browser-facing routes validate the query _inside_ the handler (behind an HTML-rendering wrapper) so a bad query still renders HTML, not the router's JSON 400.
- Channel kinds are an ENUM in the `channels` table, so adding one (`lobby`/`q`, 2026-08-25) is a Prisma migration plus **every** switch on `kind`. The ones that exist: `buildChannel`/`patchChannel`/`rotateSecret`/`channelView` (console), `createBody`/`channelsQuery` zod enums, `ChannelKind` in `@yyt/core`, the SPA's `types.ts`/`channelForm.ts`/`ChannelForm.tsx`/`ChannelNew`/`Channels`/`ChannelDetail`, and the CLI's `configFlags.build` + `channelKinds`. The trap is the trailing `else` — `channelView` and `rotateSecret` both ended in a `match` branch with no guard, so a new kind silently rendered a match `wsUrl` and minted an apiKey. Add the branch, then grep for the kind literals before believing you are done.
- The realtime gateway (`docs/realtime-gateway-design.md`) is the first component that is neither a Lambda stack nor written in TypeScript, so it shares no code with `packages/*`: every contract with it is a wire spec, not a type. Two consequences already in the code — it reads channel config over HTTP (`GET /gw/channels/{id}`, shared-secret bearer from SSM) instead of opening a MariaDB connection, and `lobby`/`q` channels carry no apiKey at all.
- Game assets are a **separate console resource** from the binary catalog (`services/console/src/assets.ts`, `@yyt/console-db` `AssetsDb`) that shares only the bucket, the CDN and the presigned-PUT plumbing (`ArtifactStore`). They exist apart precisely to avoid the catalog's per-app/per-group permission grid: reads are public at the CDN and the management API is member-read + owner-or-admin-write, full stop. When a change touches `ArtifactStore`, remember both callers — `presignPut`'s `contentType` and `copy`'s metadata argument default to the binary behaviour so catalog paths are unaffected. New route surface goes under `/assets/bundles*` and `/assets/uploads/{id}`; the two never collide because bundles never sit directly under `/assets/{name}`.
- List routes carry what a list screen renders (2026-08-27): `GET /teams/{team}/catalog/apps?artifacts=summary[&platform=]` embeds `latestArtifact` + `applicationIds` per app through `summarizeArtifacts(appIds)` (two window-function queries, `rules/data.md` raw SQL). The console app used to follow the list with one `/catalog/apps/{id}/artifacts` request per app (5 at a time, each through a fresh `http.get` connection and a Lambda that re-resolves the app and its team) — 17 requests / 6.4 s cold for 15 apps on dev versus 2 requests / 1.5 s. When a client loops over ids to call a single-resource route, add a batched view to the list route instead of tuning the client's concurrency.
- Auth channel JSON shape (console writes, auth reads): `config_json = {audience, tokenTtlSec, redirectAllowlist[], providers:{github?:{clientId}, google?:{clientId}}}`, `secret_json = {secret, providers:{github?:{clientSecret}, google?:{clientSecret}}}`. Readers live in `@yyt/console-db` (`ConsoleDb.findAuthChannel`).

## Sample game stack (`examples/sample-dungeon`)

- It is a **standalone pnpm root** (own `pnpm-workspace.yaml`, `eslint.config.mjs`, `vitest.config.ts`), not a workspace member: it depends on `@yingyeothon/*` from npm (2.0.x since 2026-08-28: server packages `^2.0.0`, `gamebase-client` `^2.0.1`; an unpublished tslib change is tested through a temporary `overrides: link:/abs/path/tslib/packages/*` that never gets committed). pnpm 11's release-age gate would otherwise refuse a freshly published tslib, so every `pnpm-workspace.yaml` (root and both samples) lists `minimumReleaseAgeExclude: ["@yingyeothon/*"]`. Root `pnpm lint`/`format`/`test` ignore `examples/**`; run its own `pnpm typecheck && pnpm lint && pnpm test` inside the directory. Keep it copy-pasteable: no `@yyt/*` imports (the callback HMAC is re-implemented in `src/signature.ts` on purpose), no SSM — everything comes from one env file.
- The match service's callback cannot target topic `POST /t` directly (signed body vs bearer + topic body): a glue route is required (`src/topicLobby.ts`). Keep `docs/decisions.md` wording ("callback target may be the topic service") read as "via a glue function".
- Games reuse the auth JWT unchanged (`docs/auth-game-contract.md` "Reusing the auth service token"); the callback response is `{wsUrl, gameId}` with no token. `members[].memberId` must be the auth `userId` byte-for-byte.
- tslib changes that this repo needs land in `~/git/yyt.life/tslib` as separate commits (the user pushes/releases): Redis ACL `username` (`REDIS_USER`), `runGameAllTogether.endDropDelayMillis`.

## Sample MORPG stack (`examples/sample-morpg`)

- The second sample: lobby on a gateway `lobby` channel, instanced dungeon on a `q` channel (tslib actor, fixed 200 ms tick, one self-contained `frame` per tick), character sheets in the doc store. Same standalone pnpm root as sample-dungeon; `examples/sample-morpg/scripts/local-api.mjs` serves the `http` handler locally from an esbuild bundle written under the project (`.esbuild/local/`, gitignored — a bundle in `/tmp` cannot resolve the externalised AWS SDK).
- **The entry API reads the roster from the gateway, never from the client**: `GET /parties/{partyId}?channel={lobbyId}` with the caller's own JWT. A participant's Redis credential is scoped to `game:{stage}:{qId}:*` and cannot see `gateway:*`, so the platform serves the read. (The store has supported read-only ACL selectors since the Valkey 8 upgrade on 2026-08-28; letting the issuer add `%R~gateway:{stage}:party:{lobbyId}:*` is `todo/16` — the gateway route stays as the fallback either way.) The route answers 404 for unknown _and_ non-member alike.
- **tslib `readyCall` accepts exactly HTTP 200** — a `204` from the readyCall sink makes the actor throw before the game loop and the party gets a `wsUrl` nobody listens on. Answer `200` with a body.
- tslib's actor fires `readyCall` only when `GameActorStartEvent.callbackUrl` is set; an entry Lambda that omits it makes "wait for ready" a silent no-op and hands clients a `wsUrl` before anything listens. A failed start retries with a **new** `gameId` (the dead actor's lock outlives it).
- **The dungeon only returns a delta** (`{exp, items, consumed, questProgress}`); `applyResult` is idempotent by `gameId` (`appliedGames`, bounded) and `commitResult` is read → apply → `PUT If-Match`, retried on 409. Members who never entered or earned nothing are `skipped` (no doc write, no version bump); the commit phase runs members in parallel under a 10 s deadline, and anything `failed`/`pending` is parked at `{prefix}pendingcommit:{gameId}:{memberId}` (24 h) with the delta in the log — the `result` frame and the socket drop must never wait on the doc store.
- A setup failure (map fetch, sheet read) still runs the loop with no world so the party receives `result {reason:"error"}` and is dropped; the map bundle is cached per container by URL (immutable by contract).
- One dungeon per party: `SET NX` enter lock (15 s) closes the race between two `enter` calls, and the party → gameId key is checked against the actor's lock key, so a finished or crashed game can be replaced but a live one answers `409 party_in_dungeon`.
- Owner ids handed to the doc store are validated against the store's grammar before they reach a URL: the apiKey is privileged and a `sub` is whatever the auth channel minted.
- The terminal client (`examples/sample-morpg/cli/`, `pnpm play`, 2026-08-28) lives **inside the sample root**, not in `apps/*`: it shares `src/map.ts`/`sim.ts`/`character.ts` types by relative import (an `apps/*` package could not — `examples/*` is outside the workspace) and a participant copying the sample gets the client with it. It runs through an esbuild bundle like `local-api.mjs` (Node's type stripping cannot follow the `./x.js` specifiers `verbatimModuleSyntax` demands). Only the caller of `POST /dungeon/enter` learns the `gameId`, so the leader relays it as a party `event` (`dungeon.start`); members accept it only from the current leader and the gateway's member check still gates the socket. All state and rendering are pure (`state.ts`, `render.ts`, `commands.ts`, `session.ts` with injected clients) so vitest covers the whole loop without a socket; facing is the sample's own `Dir` (`"n"|"s"|"e"|"w"` from `src/sim.ts`) end-to-end — it is the lobby `pos.dir` string, the `skill` command's `dir`, and the `FACING_DELTA` key, so no integer encoding sits between the key map and the wire; `terminal.ts` owns the raw-mode TTY and only decodes keypresses; the typed line lives in `state.input` (`commands.ts` `handleKey`) — `readline.createInterface` fights raw mode for echo and cursor. Root `.prettierignore` anchors the Go CLI as `/cli`, otherwise the bare `cli` entry also ignored this directory.
- The client side of the protocol is `@yingyeothon/gamebase-client` (tslib G7, 2.0.1 — `pos.dir` is a `string` `Direction`, `party` frames arrive normalised with `invited []`/`max 0`/`leaderId ""`/`members []`, so clients index `roster.members` without guards): `scripts/smoke/morpg.mjs` drives the lobby and the `q` channel through `createGatewayLobbyClient`/`createGatewayGameClient` (root devDependency, the only tslib package the service workspace depends on) and asserts the SDK's view (`peers`, `partyId`, `roster`, `map()`, `finished` on close 1000, `buildGatewayUrl` = the entry API's `wsUrl`). What the SDK cannot observe stays raw: handshake refusals are HTTP statuses before the upgrade, so `refused()` still sends the upgrade request by hand, and `scripts/smoke/gateway.mjs` keeps a hand-rolled socket on purpose because it is the wire-spec conformance test for the gateway itself. Smoke clients pass `backoff.maxAttempts: 0` + `maxHandshakeFailures: 1` — the SDK's reconnect would otherwise hide a failure behind retries.

## Go CLI (`cli/`)

- Config is per-profile (`~/.config/yyt/config.json`, `{"profiles":{name:{api,token}},"default":name}`); resolution is `--profile` > `YYT_PROFILE` > file default, and `--api`/`--token`/`YYT_API`/`YYT_TOKEN` override the resolved profile field-wise. A legacy flat file auto-migrates on load; the re-save failure is tolerated (read-only config dirs). When a token override is in effect, `Config.Profile` is blanked so `whoami` never claims a profile it is not using.
- Cobra: a local flag on a subcommand silently shadows a same-named persistent flag (the global `--profile` vs deploy's build profile forced the rename to `--build-profile`). Also, adding subcommands under a positional-arg command (`artifact upload android|ios`) makes those literals unusable as the first positional — accepted trade-off, documented in README.
- `catalog deploy` safety rules learned from review: verify uploads by artifact **id** (a version-tag count false-passes on re-deploys and cross-platform uploads); delete matching build outputs before running `flutter build` (a stale `app-<abi>-<profile>.apk` from a wider `--target-platform` would otherwise be uploaded under the new version); refresh-login must default to the profile's stored API, never the prod default.
- Atomic config writes need `os.CreateTemp` (unique name) + explicit `Chmod(0o600)`; a fixed `file.tmp` path lets two concurrent writers corrupt each other and `os.WriteFile` keeps a stale tmp file's looser mode.
- Consumer-repo deploy scripts default to `YYT_PROFILE=dev` because the legacy app history was imported into the dev console only; a script that reaches prod by accident auto-creates the app there (`catalog deploy` on 404). Keep the profile explicit in every shared script.
- `catalog deploy` verify step retries the artifact list up to 5 times and matches by upload **id** (`--no-verify` to skip); `--build-profile` is the build flavour (`debug|release|appbundle|aab|all`), `--profile` is the config profile.

## Go gateway (`gateway/`)

- Second Go module (`github.com/yingyeothon/service/gateway`), not in the pnpm workspace and sharing nothing with `cli/`; CI runs `go vet`, `go test -race` and a Docker build for it. It has **no** TypeScript twin: every contract with tslib (`UserMessage` envelope, `GatewayCommand`, start-event membership) and with clients (`hello`, frame set, close codes) is a wire format written down in `gateway/README.md` — change that file in the same commit as the Go code, and treat it as the client SDK's contract (`tslib` G7).
- Layering: `config` (env) → `console` (channel config over HTTP, 60 s cache, singleflight) → `authn` (verify via auth, cached until `exp`, singleflight) → `conn` (one socket: bounded outbound queue that drops the _oldest_, inbound cap, token bucket, ping/pong, close codes) → `lobby.Hub` / `q.Bridge` (one per channel, one mutex each, sends are non-blocking queue pushes so they may run under the lock) → `server` (handshake, strategy routing, refresh loop, drain). Strategies take a `Socket` interface so tests use a recorder instead of a WebSocket; `server` tests dial the real thing against `httptest` console/auth fakes and `miniredis`.
- Handshake refusals happen **before** the upgrade with an HTTP status, so a browser gets a real error instead of an opaque close; after the upgrade every refusal is a typed `error` frame and repeated abuse closes with `4003`. Never reject silently — silence during a contest is expensive to debug.
- The gateway holds no channel secret and no MariaDB connection by design; if it ever needs a new console read, add a route under `/gw/*` behind the shared token rather than a database client.
- Hub/bridge locking rules learned in review: never do Redis I/O while holding the hub or bridge mutex (party persistence is decided under the lock and executed after it via `persist`/`runAfter`; a game's `SUBSCRIBE` runs outside the lock behind a `ready` channel), send `hello` **inside** the first locked section (once the user is in `byUser` a whisper or roster change could otherwise be queued first — and a test that reads `hello` must then wait for `snapshot` before assuming the player is in the zone), and make `Join` refuse (`false`/`ErrStopped`) once `Stop` ran so the server's refresh loop can drop an empty hub without stranding a socket on it — the handler retries `hubFor`. An abort must be terminal (`ErrAborted` on rejoin) and must not fire for a game already dropped from the map, or a late `leave` push would `DEL` its successor's queue.
- A wire contract with a component in another language (Go gateway ↔ tslib) must name every field and enum value numerically in a spec; when the same name must agree on three sides (gateway, library, participant config) derive it from one id instead of configuring it — a mismatch is a silent no-op, not an error. The `q` channel prefixes in `rules/data.md` are the worked example.
