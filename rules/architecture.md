# Architecture

- Layout: `packages/*` (shared libs: core, redis, jwt, http, ws, console-db), `services/{auth,console,topic,match,state}` (one Serverless stack each), `apps/console-web` (React+Vite SPA), `cli/` (Go), `scripts/`, `examples/sample-dungeon` (tslib integration).
- Console SPA (`apps/console-web`) is mounted at `/ui/` on the console API host: the session cookie is `__Host-` (same host required) and the API owns the root paths (`/events`, `/channels`), so SPA routes must not collide. `WEB_URL` (login landing) is `https://{domain}/ui`; `next` is the router-relative path. Keep `vite base`, `BrowserRouter basename`, `WEB_URL` and the CloudFront `/ui/*` behavior (todo/07) in sync. UI stack (2026-08-24): Mantine 8 + `@tabler/icons-react` (compact light-only theme in `src/theme.ts`, AppShell layout) and TanStack Query 5 via `src/lib/query.ts` `useApiQuery` — `staleTime: 0` keeps the old refetch-on-mount semantics, `set` writes through to the cache; the auth provider calls `queryClient.clear()` on logout/401 so cached rows never outlive a session. `src/navigation.ts` NAV_ITEMS is the single source for both the side menu and route guards (`App.tsx` `navMinRole`).
- Services depend only on `packages/*`; never import another service's `src`. Cross-service data goes through the console MySQL database (SELECT-only accounts for auth/topic/match; `state` additionally writes `state_docs` and nothing else) or Redis.
- The console stack owns the schema and every migration, and is the only writer of every table **but `state_docs`** (`state`, 2026-08-26). auth/topic/match/state read channel config through the same `@yyt/console-db` repository with their own account; rows with secrets (auth channels) are never cached in Redis.
- The `state` stack (`services/state`, `doc{-dev}.yyt.life`) serves the **doc** storage shape and nothing else. It is the pattern to copy for a stack that only needs MySQL: no Redis client, no `REDIS_*` env, no schema of its own, one route table. Its document namespace hangs off the **auth** channel, because `ownerId` is `deriveUserId(authChannelId, …)` and means nothing outside it — which is also why its routes need no channel segment and its apiKey carries the channel id instead (`newDocKey`/`docKeyChannelId` in `@yyt/core`).
- Follow tslib API conventions (`~/git/yyt.life/tslib/CONVENTIONS.md`): `create*` factories returning interfaces, no exported classes, options object when >2 params or any optional param, no `process.env`/`console.*` inside `packages/*` (handlers read env once and pass options), `logger?: Logger`.
- Keep the JWT claim contract (`iss=yyt-auth/{channelId}`, `aud`, `sub=userId`, `exp`) identical to `docs/auth-game-contract.md` so tslib's `createJwtRequestAuthorizer` verifies our tokens unchanged.
- Team → Project → Resource (2026-08-26, `docs/decisions.md` _Teams and projects_): every channel/app/bundle row carries `team_id` + `project_id` (nullable until the contract migration), and authorization is team membership read through `TeamDb` (`@yyt/console-db` `src/team.ts`). `owner_id` survives only as `createdBy` for display. The rework lands on branch `orgproj` in stage-sized commits (`todo/17-team-project.md` §6).
- Never add new persistence technologies (DynamoDB, RDS) — the decision is self-hosted MariaDB + Redis (`docs/decisions.md`). Reopen `docs/decisions.md` if that proves insufficient.
- Do not port legacy repos' build layers (node8–14, webpack); only port algorithms (`lobby-api/src/match`) with fresh tests.
- Storage packages expose a repository/`Kv` interface plus an in-memory fake (`createMemoryConsoleDb`, `createMemoryKv`); services and tests depend on the interface, and only `handler.ts` constructs the real driver (`createMysqlDb`/`createRedisKv` from `*OptionsFromEnv()`), once per container.
- Packages are built with `tsc -p tsconfig.build.json` into `dist/` (ESM only, `exports["."]`), and services bundle them with esbuild; `pnpm -r build` must run before a service bundle or typecheck. `package.json` `main/types` point to `dist` — no `src` fallback.
- Handlers return plain objects (→ 200 JSON), `undefined` (→ 204) or an `HttpResult`; throw `AppError` for every client-visible failure so the router maps status/code uniformly.
- Route tables: wrap routes in `defineRoute({...})` from `@yyt/http` so `body`/`query` zod inference flows into the handler; the table type is `AnyRoute[]`. Browser-facing routes validate the query _inside_ the handler (behind an HTML-rendering wrapper) so a bad query still renders HTML, not the router's JSON 400.
- Channel kinds are an ENUM in the `channels` table, so adding one (`lobby`/`q`, 2026-08-25) is a Prisma migration plus **every** switch on `kind`. The ones that exist: `buildChannel`/`patchChannel`/`rotateSecret`/`channelView` (console), `createBody`/`channelsQuery` zod enums, `ChannelKind` in `@yyt/core`, the SPA's `types.ts`/`channelForm.ts`/`ChannelForm.tsx`/`ChannelNew`/`Channels`/`ChannelDetail`, and the CLI's `configFlags.build` + `channelKinds`. The trap is the trailing `else` — `channelView` and `rotateSecret` both ended in a `match` branch with no guard, so a new kind silently rendered a match `wsUrl` and minted an apiKey. Add the branch, then grep for the kind literals before believing you are done.
- The realtime gateway (`todo/14-websocket-gateway.md`) is the first component that is neither a Lambda stack nor written in TypeScript, so it shares no code with `packages/*`: every contract with it is a wire spec, not a type. Two consequences already in the code — it reads channel config over HTTP (`GET /gw/channels/{id}`, shared-secret bearer from SSM) instead of opening a MariaDB connection, and `lobby`/`q` channels carry no apiKey at all.
- Game assets are a **separate console resource** from the binary catalog (`services/console/src/assets.ts`, `@yyt/console-db` `AssetsDb`) that shares only the bucket, the CDN and the presigned-PUT plumbing (`ArtifactStore`). They exist apart precisely to avoid the catalog's per-app/per-group permission grid: reads are public at the CDN and the management API is member-read + owner-or-admin-write, full stop. When a change touches `ArtifactStore`, remember both callers — `presignPut`'s `contentType` and `copy`'s metadata argument default to the binary behaviour so catalog paths are unaffected. New route surface goes under `/assets/bundles*` and `/assets/uploads/{id}`; the two never collide because bundles never sit directly under `/assets/{name}`.
- Auth channel JSON shape (console writes, auth reads): `config_json = {audience, tokenTtlSec, redirectAllowlist[], providers:{github?:{clientId}, google?:{clientId}}}`, `secret_json = {secret, providers:{github?:{clientSecret}, google?:{clientSecret}}}`. Readers live in `@yyt/console-db` (`ConsoleDb.findAuthChannel`).

## Sample game stack (`examples/sample-dungeon`)

- It is a **standalone pnpm root** (own `pnpm-workspace.yaml`, `eslint.config.mjs`, `vitest.config.ts`), not a workspace member: it depends on `@yingyeothon/*` which is unpublished and resolved through `overrides: link:../../../tslib/packages/*`. Root `pnpm lint`/`format`/`test` ignore `examples/**`; run its own `pnpm typecheck && pnpm lint && pnpm test` inside the directory. Keep it copy-pasteable: no `@yyt/*` imports (the callback HMAC is re-implemented in `src/signature.ts` on purpose), no SSM — everything comes from one env file.
- The match service's callback cannot target topic `POST /t` directly (signed body vs bearer + topic body): a glue route is required (`src/topicLobby.ts`). Keep `docs/decisions.md` wording ("callback target may be the topic service") read as "via a glue function".
- Games reuse the auth JWT unchanged (`docs/auth-game-contract.md` "Reusing the auth service token"); the callback response is `{wsUrl, gameId}` with no token. `members[].memberId` must be the auth `userId` byte-for-byte.
- tslib changes that this repo needs land in `~/git/yyt.life/tslib` as separate commits (the user pushes/releases): Redis ACL `username` (`REDIS_USER`), `runGameAllTogether.endDropDelayMillis`.

## Go CLI (`cli/`)

- Config is per-profile (`~/.config/yyt/config.json`, `{"profiles":{name:{api,token}},"default":name}`); resolution is `--profile` > `YYT_PROFILE` > file default, and `--api`/`--token`/`YYT_API`/`YYT_TOKEN` override the resolved profile field-wise. A legacy flat file auto-migrates on load; the re-save failure is tolerated (read-only config dirs). When a token override is in effect, `Config.Profile` is blanked so `whoami` never claims a profile it is not using.
- Cobra: a local flag on a subcommand silently shadows a same-named persistent flag (the global `--profile` vs deploy's build profile forced the rename to `--build-profile`). Also, adding subcommands under a positional-arg command (`artifact upload android|ios`) makes those literals unusable as the first positional — accepted trade-off, documented in README.
- `catalog deploy` safety rules learned from review: verify uploads by artifact **id** (a version-tag count false-passes on re-deploys and cross-platform uploads); delete matching build outputs before running `flutter build` (a stale `app-<abi>-<profile>.apk` from a wider `--target-platform` would otherwise be uploaded under the new version); refresh-login must default to the profile's stored API, never the prod default.
- Atomic config writes need `os.CreateTemp` (unique name) + explicit `Chmod(0o600)`; a fixed `file.tmp` path lets two concurrent writers corrupt each other and `os.WriteFile` keeps a stale tmp file's looser mode.
