# Testing

- Core logic (matching, lock, token issue/verify, state machines) must not import drivers, AWS SDK or fetch directly; inject `Kv`, `ConsoleDb`, `fetch`, and clock so unit tests run without network or Docker.
- Redis: test against `createMemoryKv()` (in `packages/redis`), which must mirror the Redis semantics used in code (NX/EX, TTL expiry via injected clock, list/set ops, eval for lock release). `kvContractTests` runs the same cases against the fake and, with `YYT_IT=1`, the real dev Redis.
- MySQL: behavioural contract suites (`eventsContract`/`catalogContract`, exported from their test files) run against both the in-memory fakes and the real Prisma repositories on a **testcontainers MariaDB** (`test/testDb.ts` starts `mariadb:11` and applies the same `prisma/migrations/*` SQL that `migrate deploy` runs). The container suite skips cleanly when Docker is absent (`YYT_TC=0` forces skip), so `pnpm test` still works Docker-less at reduced coverage. `YYT_IT=1` adds a real round-trip on the dev DB (unique ids, cleaned up in `afterAll`). Integration tests must open one connection per suite — the host allows few.
- S3: `aws-sdk-client-mock`. Provider HTTP (GitHub/Google): undici `MockAgent`.
- No task is complete without tests for the new behavior. Target vitest coverage ≥80% lines / ≥70% branches per package, like tslib.
- WebSocket handlers: test the pure handler functions with synthetic API Gateway events; test the poster with a fake transport that records `send`/`drop`.
- CLI: `httptest` servers + golden output files.
- `createMemoryKv` does not run Lua: `eval` pattern-matches the scripts this repo ships (currently only compare-and-delete). Adding a new script means adding a matcher in `memoryKv.ts` and a case in `kvContractTests` so the real-Redis run (`YYT_IT=1`) keeps the fake honest.
- Inject `clock` _and_ `sleep` into `withLock` in tests; advancing the fake clock inside `sleep` makes timeout tests deterministic without timers.
- Provider HTTP via undici `MockAgent`: wrap `undici.fetch` with `{ dispatcher: agent }` and inject it as the provider's `fetch`; serve Google's JWKS through the same mock so `createRemoteJWKSet` (jose `customFetch`) runs the real path. Mint test id_tokens with `generateKeyPair("RS256")`.
- WebSocket services: `test/helpers.ts` `join()` replays what API Gateway does (`$connect` with the socket still pending → worker event → probe succeeds) so matcher tests exercise the real ordering; the fake transport's `pending`/`gone` sets drive `probe`/410.
- Assert on distinctive sentinel strings (e.g. `c0de-secret-zz`) when checking that a secret never appears in a response — short words collide with legitimate error text.
- Go gateway (`gateway/`): Redis behaviour is tested against `miniredis` (real RESP semantics incl. pub/sub, TTLs and the compare-and-delete script — no fake to keep honest); strategy tests drive `lobby.Hub`/`q.Bridge` through a recorder `Socket`; `server` tests dial a real WebSocket against `httptest` console/auth fakes. Time is injected (`Now`) so abort timeouts and cache expiry are deterministic; `go test -race` is part of CI. When a per-channel counter is added, add the balance test (`stats_test.go` pattern: join, replace, leave — back to zero) — an unbalanced gauge is invisible to every other test and permanent in `/metrics`.
- A memory fake must fail at the same point the real driver fails. A fake that throws _before_ mutating lets "a failed issue leaves no credential behind" pass while the real path (mutate, then fail on persist) makes it false. Give fakes `failNext(method, "before" | "after-mutation")` and throw the same error class the real client maps to (`AppError("unavailable")`); put the same input guards (e.g. the `game_` username check) in the fake, or routes never exercise them in unit tests.
- A fake that backs a `utf8mb4_bin` column must sort like it: `localeCompare` puts `map.json` before `MAP.json`, MariaDB binary collation the reverse, and a contract test that passes only against the fake is lying about the database.
- When a route can answer with a status instead of a value, assert the status too. "A re-issue returns a different password" kept passing after a 429 was added because `undefined` is `not.toBe` the old password.
- Test a cron/sweep step through the function the handler calls, not by re-implementing the wiring in the test: with the wiring re-implemented, deleting the line in `handler.ts` kept the suite green. Extract the step (`runRedisAclReconcile` pattern) and call it directly.

## Ordering and time (2026-08-29)

- A list ordered by `(created_at, id)` is only deterministic when the id is time-ordered. Poster uploads minted `ep_${randomHex(6)}`, two uploads landed in the same second on dev, and the events smoke flipped between passes — a unit test with the fake clock never sees it. Use `ulid().toLowerCase()` for any id that serves as a sort tiebreaker (posters, comments); keep `randomHex` only for ids that are never ordered.
- A smoke that waits for a real deadline must set the deadline **right before** the transition it exercises (`PATCH voteUntil` just before `publish`), not at script start: a cold Lambda plus an S3 round trip is enough to push a fixed 20 s window past `publish` and turn one slow call into a cascade of unrelated FAILs.
- Fresh-context reviews of a schema+API+CLI+SPA change (this one: 3 agents, ~7 min) found four real defects the 600-test suite did not — two contract gaps (a private state reachable from `draft`, an admin permission the decision grants), one missing cross-cutting rule (the write slot) and one lost-bookkeeping path (hard delete after a failed S3 delete). Budget for them; they are cheaper than the dev round trip that would have found the same.

## Golden-review lessons (2026-08-28)

- An invariant stated as "every X has Y" is cheap to turn into a test once the set of X can be enumerated: `test/serverless-invariants.test.ts` (root vitest project `repo`, `yaml` parses every `services/*` + `examples/*` `serverless.yml` with `logLevel: "silent"` because CloudFormation tags are unknown to it) checks `reservedConcurrency` on every function and pins the list of stacks, and `redisx_test.go` reflects over the client's exported methods so an unlisted write helper fails. "Nothing logs a credential" still has no enumerable set, so it stays review-enforced. When such an invariant is reviewed, grep the whole tree **including `examples/*`** — that is where the 2026-08-28 review found the only violation (seven example functions without `reservedConcurrency`) — outside the MariaDB budget the rule was written for, but copied verbatim by participants, so the knob and a peak-sized number (`rules/serverless-aws.md`) matter there too.
- The q bridge's "opaque payload" is field-level, not byte-level (it re-encodes the object to strip `memberId`); tests assert untouched fields, not identical bytes. Keep it that way — a byte-level promise would need a streaming rewriter for no gain.
- Any id grammar like `[a-z0-9_-]+` admits `constructor`, `__proto__`, `hasownproperty`; a `Record<string, T>` lookup with such a key returns an inherited function, which is truthy. Guard every lookup on user-supplied keys with `Object.hasOwn` (sample-morpg `character.ts` `own()`), and test those three names explicitly.
- Numbers that round-trip through JSON (parked/replayed deltas, doc rows) can be `Infinity`/`NaN` (`1e400` parses to `Infinity`, serialises back as `null`); clamp with `Number.isFinite` at the apply site, not just at parse, and test `Infinity` once per accumulator.
- A `switch` over a wire event union must be exhaustive **and** carry a `default` (`const unknown: never = e` keeps the compile-time check): the actor and the client deploy separately, so a client build older than the server will receive event names its union lacks, and a bare exhaustive switch returns `undefined` into the render path (morpg `describeEvent`, 2026-08-29). Also: a guard that only runs on a failing branch (`if (!r.ok) throw new Error(r.code)`) is checked by `tsc`, not by vitest — run typecheck, not just tests, on a package before calling it green.
