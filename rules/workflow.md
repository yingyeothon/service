# Workflow

## Per-task completion ritual

1. Make the change testable and cover new/changed behavior with vitest (or `go test` for the CLI).
2. Manually verify on the `dev` stage with curl/wscat or `scripts/smoke/*` (see `manual-verification.md`).
3. Run three fresh-context subagents to adversarially review the change (correctness, security, operability).
4. Apply the review feedback.
5. Record reusable lessons in `rules/*.md`; update `rules/index.md` if files changed. Update `todo/index.md` (status table, progress log with absolute date, next work) and tick the area checklist.
6. Commit to `main` with an imperative message and push to `origin` (`git@github.com:yingyeothon/service.git`). No PRs unless branch protection appears.

## Documentation discipline

- `docs/decisions.md` is the contract. If implementation forces a change, edit the doc in the same commit and note it in `todo/index.md`.
- Do not leave work in chat only: anything a future session needs must be in `todo/` or `rules/`.
- **A summary document needs a status vocabulary, or it over-claims by default.** `docs/platform-overview.md` (2026-09-22) first described the game kit, `/presence` and the wire packages in the same present tense as five deployed stacks; a reader comparing SDK maturity would have scored a design document as a shipped library. Any doc that spans the whole platform states, per capability, whether it is deployed on both stages, merged but not running, or decided and unbuilt — the three states this repository actually has, because a stack deploy, a container recreate and a client-library release are three different people's work.
- **A comparison document is a third kind of doc, and it is not a shorter `decisions.md`.** Its unit is the axis a reader can also ask of another product, so a paragraph that no competitor could answer (how this repository records decisions, how presigns count against a cap) is padding however true it is, while an absence with a reason is content. `docs/platform-overview.md` is the one of these; keep new material out of it unless it changes an axis.
- A scope qualifier in `docs/` is a deferral, not a policy: "grid bucketing and radius config are explicitly not built **at this scale**" was read as "the gateway will never do AOI", and the review built on that for a whole session before the owner corrected it (2026-09-01, `todo/26`). When a sentence rules something out, say whether it is _not yet_ or _not ever_, and when reading one, check the protocol before trusting the prose — `pos` had carried `(x,y)` from day one, which no relay needs unless it intends to filter by them. The same rule as the seatless-admin case (2026-08-29): a restriction the assistant inferred is not "by design".
- Commit per coherent unit; never `git add .` when generated files are present. Keep `.gitignore` current.
- Sessions start by reading `todo/index.md` → "Next work"; sessions end by updating the same section.
- Retiring a todo doc: fold design into `docs/`, lessons into `rules/`, leave only unchecked items in `todo/`; move the retired file into gitignored `local/todo-archive/` instead of deleting it — `todo/` is outside git, so a delete is permanent. Owner-only tasks (browser passes, OAuth app registration, external accounts, private ops-repo work) go to `local/owner-checklist.md`; optional/deferred items and pending owner decisions go to `todo/34-backlog.md`, whose "결정 필요" entries a session resolves with AskUserQuestion before promoting to a new `todo/NN`. `docs/`/`rules/` are public: operational identifiers go to gitignored `local/ops-notes.md`.
- Review the plan before the code when a change spans schema + services + clients (team/project rework, 2026-08-26): three fresh-context adversarial reviews of the plan document (consistency / security & permissions / operations & migration) found 6 blockers and ~20 majors, all real, before a line was written.
- A phase must be a self-contained commit: when a schema column becomes required later, keep the input type optional in the expand phase — making it required early breaks every stack that bundles the same Prisma client (console, auth, state) in one commit.

- **Run the container suite whole, not sliced.** `pnpm vitest run prisma.tc.test.ts -t "<one contract>"` is the fast way to iterate on a new repository, and it is also how a change ships with the suite red: adding a field to `ProjectResourceCounts` broke an unrelated fixture in the same file, and every other gate stayed green (2026-09-10, found by review). The last run before a commit is the unsliced one.
- **A retroactive grammar change gets its own commit, and the check that clears it is usually one a session can run itself.** Adding `lb` to `ID_LIKE`/`idLike` (three copies: `services/console/src/team.ts`, `services/console/src/channels.ts`, `cli/internal/cmd/context.go`) forbids a name a resource may already carry, so both stages were queried for `name LIKE 'lb\_%'` across teams, projects, channels, apps, bundles, sites, kv collections and versions first — both empty, 2026-09-10. The owner checklist had assumed the classifier would block that, and it does not: it blocks **mutations**, not a read-only `SELECT` through `local/env/*.env`. Write such a gate as "run this query" rather than "ask the owner", and only escalate what actually fails.

## Deduplication passes (`nose`, 2026-09-02)

- `nose query . --exclude 'node_modules/**' --exclude 'dist/**' --exclude 'coverage/**' --exclude '**/*.md' --exclude '**/generated/**' --exclude '**/.serverless/**'` ranks duplicated families; `id=<fam> full` prints the copies with a diff, `group=dir` the concentration. Read every flagged region before acting: roughly a third of the families differ in policy (timeouts, cap semantics, required vs optional fields, the examples' deliberate copies) and folding those would change behaviour or need more parameters than lines saved.
- A dedup refactor is behaviour-preserving only when each call site passes its **current** literal (message, TTL, flag) to the helper — the `git diff` at the call site must show the same string that was there before — and untested production code (handlers, S3 stores, SPA tabs) gets a test pinning today's output _before_ it is refactored.
- `--baseline local/nose-baseline.json --fail-on new` is location-sensitive: any edit that shifts lines re-flags the families below it as "new", so it is not a CI gate here. Track progress by family id from the pre-pass report (`local/nose-before.md`) and re-write the baseline after each commit.
- Copies that have silently drifted (one side gained a guard the other lacks) are findings for the owner, not things a dedup fixes in passing — list them in the todo doc and leave both sides as they are.

## Console SPA (`apps/console-web`)

- `pnpm -r build` now runs `vite build`; `pnpm lint`/`typecheck` cover `.tsx` (type-aware ESLint via `projectService`). SPA tests run under the root `pnpm test` (`vitest.config.ts` projects include `apps/*`) but are excluded from the coverage thresholds on purpose.
- When a console route changes shape, update `src/types.ts` + `src/api.ts` and the affected page in the same commit (same rule as the CLI). And when the route _gains_ a field the page reads without a guard (the admin listing row's `artifacts`, 2026-09-29), the API deploys before `deploy-web.sh` on every stage — the two scripts are separate commands and nothing else enforces the order; the old SPA against the new API is always fine, the reverse crashes the page for the role that reads the new field.
- **Page grammar (2026-09-02, `todo/30`)**: every page is a List, a Detail, the one Form page (`channels/new`) or a Utility page, built from `src/components/{PageHeader,Section,DataTable,FilterBar,ResourceDrawer,RowMenu,EmptyState,ReadOnlyBanner,Loading}.tsx` with `src/lib/notify.ts` and `src/lib/confirm.tsx`. The rules the kit encodes, so a page never invents its own arrangement:
  - The header renders before the data: pass `title={data?.name}` (a skeleton bar while undefined) and put the body behind `data ? … : error ? <Notice/> : <PageSkeleton/>`. Never `return <Spinner/>` above the header — the old pages hid their own title while loading.
  - One filled button per viewport, and it is the header's: the list's `New <noun>` or the detail's one primary verb (`Publish event`, `Put something up`). Section actions (`New project`, `Add member`, `Grant access`, `Run cleanup`) are white `variant="default"` buttons; red outline exists only in the drawer's danger zone. `Edit` is always the first white button on a detail page; destructive verbs go to the overflow menu (`danger: true`) or a `RowMenu`, never a button in the header, and the overflow carries a delete only when the drawer is out of reach (a seatless admin on Team/Project/Channel, a non-author owner on a discussion). In-row controls are three: `Approve` on a pending seat (the row's one fast path), the `Show files`/`Detail` buttons — legitimate because what they open is a payload of its own, a file listing or an audit body, and since `todo/51` (2026-09-29) they open it in a read-only `ResourceDrawer` (`hideFooter`, the limit request's `Details` shape) so nothing ever renders below a table — and the catalog artifact's changelog cell, which is its own `UnstyledButton` because a row's own fields belong in the row, not in a panel below the table. A settings-like form that is not a list (the installer app on `/members`) is a `Section` with a status line and a white `Edit` that opens the edit drawer, whose danger zone carries the clear. What every such surface owes by default — the page's column budget, one-line rows, a tap equivalent for anything hover-only, keyboard and AT, theme tokens, CLI parity, and a browser measurement for any layout claim — is [ui.md](ui.md); it was written after three rounds of owner corrections on one table (2026-09-03) and is the list that should have made them unnecessary. A platform admin acting on someone else's show sends a reason on every write (submit, grant, revoke, update, close, delete).
  - Create and edit both open a right `ResourceDrawer` (`useDrawerForm` resets the values on every open); the edit drawer's foot is the `danger` zone. `onSubmit` closes the drawer only when the request returned a row (`useAction.run` is `undefined` on failure; map a 204 to `true`). The channel create form stays a page because it is long, kind-switched, and navigates away carrying the once-shown secret.
  - Destructive actions confirm in a modal via `useConfirm()` whose button repeats the verb (`Delete team`, `Kick alice`, `Revoke token`, `Yes, close it`); a `reason` option adds the required field for an admin acting on someone else's content. The hook runs `modals.closeAll()` on unmount, so no page needs to. The two-click `Confirm` is gone; do not bring it back.
  - Success is a toast (`notify.created/saved/deleted/done`); errors stay inline (`Notice kind="error"` in the drawer or under the section). Never a green `Notice` for success unless it carries data the user must act on (the rotation list after leaving a team).
  - Tables are `DataTable`: scroll container, hairline rows, tabular figures, and the loading/error/empty states inside the table area; the first cell is `NameCell` (an `after` slot keeps badges out of the link's accessible name). Filters are `EnumFilter` (≤4 values segmented, more a native select) and the free-text `TextFilter`, both applying on change; the audit log's free-text pair is the only `Apply`.
  - **Ordering and search are the server's (2026-09-02, `docs/decisions.md` _List sort and filter_)**: a column with `sortKey` (a response field name; `defaultOrder: "desc"` for times and counts) renders its header as a `<button>` with `aria-sort` on the `th` and cycles default → other → the server's order; the page owns the state through `useListQuery()` (`sort`, debounced `q`, and `params` that carries no `undefined` keys, so it is both a query-key member and the exact argument a test asserts). Pass `keepPrevious: true` to `useApiQuery` so a re-sort keeps the rows on screen (`fetching` dims them), and swap the empty state to `noMatch(q)` while a search is set. Never reorder or filter rows in the page. A header label must not collide with an action button's name (`Deploy id`, not `Deploy`), because the header _is_ a button now. A list embedded in a detail (site deploys, show grants) asks the list route only once a sort is chosen (`enabled: !!lq.sort`), shows `loading || fetching` as busy on that first pull, and is reloaded beside the detail after a write. Pass `useListQuery({ scope: id })` in any section that stays mounted across a route change — `keepPrevious` would otherwise paint the previous team's rows under the new team's header until the fetch lands. A filter whose value the server refuses in another mode (an admin's `sort=role` under `scope=all`) must be cleared by the switch that changes the mode, because a query error drops the placeholder rows and the header button with it.
  - A resource that owns sub-lists (a version's links and the issues referencing it, 2026-09-02, `todo/32`) is a Detail page with a route and `NameCell` links into it, not a drawer: a drawer holds one form, and a drawer with two forms plus a table was the sign the version had outgrown it. Rows that can repeat (three per-ABI artifacts of one deploy) must carry what tells them apart in their label, or their `Actions for …` menus share one accessible name. Per-row facts are not enough on their own: two re-uploads of one version share platform, ABI **and** file name (the object key differs only in its upload id), so build the labels over the rendered list and append the id to the ones that repeat (`artifactLabels`, 2026-09-03) — every control in the row (menu, expander, confirm title) uses that one label.
  - Sections (`Section`, an `h2`) stack with hairlines; no cards inside cards. `PageHeader` renders the page's only `h1`. Read-only standing is one `ReadOnlyBanner` sentence plus an optional detail.
  - Heavy single-use dependencies load lazily (`todo/51`, 2026-09-29): the `/app-login` route is a `React.lazy` element under one `Suspense` in `App.tsx`, and `Markdown` renders its body through a lazy `MarkdownBody` (react-markdown + plugins, 162 kB, out of the index chunk; the index went 659 → 469 kB). Consequences: never re-export anything from `Markdown.tsx` statically, any test that renders markdown awaits it (`findByText`, not `getByText`), and `markdownLazy.test.tsx`/`routes.test.tsx` pin the split by mocking the library and asserting the mock factory never ran on import. `useDrawerForm().open` is stable (the initial-values arrow is read through a ref), so an effect may depend on it — the `/…/settings` bookmark redirect does.
  - Tests: `test/wrap.tsx` mounts the full provider stack with `env="test"` (no transitions, no portals) — drawers and modals are `findByRole("dialog")`, row verbs are `Actions for <name>` → `menuitem` → the same-named button in the dialog. Mantine `Select` still needs raw `fireEvent`. `test/kit.test.tsx` pins the kit; a page test pins labels, columns, hrefs, payloads and gating.
- The side navigation nests the caller's teams under _Teams_ as a flat indented `role="group"` of links (`useMyTeams`, key `["teams", "nav"]`); a Mantine `NavLink` given children calls `preventDefault` on its click, so a collapsible parent cannot itself navigate — do not reintroduce one. The parent gets `end` while a team is open, or both links announce `aria-current="page"`. Every team create/rename/leave/delete calls `useInvalidateTeams()` (prefix `["teams"]`), because `useApiQuery.reload`/`set` touch one key only and a missed call shows a stale name until reload.
- Every route lives in `src/routes.tsx` with the `NAV_ITEMS` path that guards it; `test/routes.test.tsx` proves each guard resolves, so a new page that forgets its nav item fails in CI rather than on a user's screen. Items that must guard without appearing in the menu use `hidden: true`; the project sub-tree (`…/channels/new` included) is guarded by `/teams`.
- `ModalsProvider` must sit **inside** `QueryClientProvider` and the router: `modals.open` renders its children in the provider's portal, and a modal that queries or navigates crashes otherwise. `Modal` sits at z-index 300 so a confirm opens over a drawer (200).
- `useAction.run` returns `undefined` on error; a call whose success is _also_ `undefined` (a 204) must map success to a sentinel (`?? null`, `return true`) before deciding what to do next, and never read `act.error` inside the same closure — it is the value from the render that created the closure, not the one `run` just set.
- What a page may do follows the caller's standing in the team (`useTeamStanding` → `GET /teams/{id}.role`), not the platform role: a seated platform admin writes like any member, a seatless one only reads (`secret: true` routes answer 403), so "delete team/project" is gated on `owner || standing === "admin"`, never on `me.role`.
- TanStack Query defaults: `staleTime: 0` (lists must refetch after a mutation), `queryClient.clear()` on logout/401 (no cross-account cache), a `queryFn` must never resolve `undefined` (use a `null` sentinel for "hidden/403" cards so the error surfaces instead of hanging), and do not put a status filter into a query key when a transition moves the item between statuses (it flashes a spinner) — unless the query passes `keepPrevious: true`, which keeps the previous rows as placeholder data while the new key loads (what every sortable list does).
- Design tokens live in `apps/console-web/DESIGN.md` and reach Mantine only through `src/theme.ts` (`ink` primary, `link` for anchors and the focus ring, radius by role, shadows zeroed) and the `--yyt-*` variables in `styles.css`. Inter is self-hosted (`@fontsource-variable/inter`) because the CSP's `font-src 'self'` forbids a font CDN; the signature colour surfaces appear in exactly two places (the Home hero, the shown-once secret banner).
- A Mantine `NumberInput` bound to a `number` field breaks the moment the user clears it (`onChange` hands back `""`, the page coerces it to `0`, `min={1}` clamps on blur, and the request carries `1`): keep the form field as `number | string`, pass the raw value through, and narrow with one predicate (`capOk`) both for the submit gate and inside the submit (`todo/33` S6, 2026-09-05). Related: `eslint --fix` removes an `as KvScope` on an object-literal initial state as "unnecessary", which widens the field to `string` and fails `tsc` — type the state with an interface (`useDrawerForm<Form>`) instead of asserting each literal.
- A cursor-paged table under filters (`useEntries` in `pages/KvCollection.tsx`): the first page is a query keyed by the filters (`keepPrevious`), the appended pages are local state tagged with the first page's object identity, so a filter change or a reload drops them by construction rather than by an effect that has to remember to.
- **An API refusal that belongs to one field is shown under that field** (the site Domain field, 2026-09-26): catch it inside the `useAction.run` callback, set the field's error, and return `undefined`, so the drawer's general notice stays empty; only what the field cannot explain (a busy site) goes to the notice. Read `status` and `details` off the error object rather than `instanceof ApiError` — the tests' `ApiError` mock carries no fields.
- **A drawer's PATCH compares the form with the values the drawer opened with, never with the live polled row** (the site Domain field, 2026-09-26): the page polls every 3 s while a move runs, so a field seeded once and compared with the fresh row turned an untouched Save into `domain: null` and undid the move that had just landed. `useApiQuery` returns `errorStatus` for status-based decisions (404 stops a poll, other errors keep it).
- `components/Clipped.tsx` (a code value) and `components/FoldCell.tsx` (any one-line label with a folding detail, 2026-09-28) (shared since 2026-09-26, `prefix` prop) is the one way to ellipse a long value inside a table cell with a tap/hover reveal. Measured in headless Chrome for the site deploy table: a 32-character move target beside a long error code needed 1079–1095 px against the 1048 px the page has at 1080; clipped at 18 characters it needs 1039 px and every row stays one line.

## Console app (`apps/console-app`, Flutter)

- **The `yyt` CLI's default profile on this machine is prod** (2026-09-29, `todo/49`): a catalog upload meant for dev verification went to the prod catalog because the command had no `--profile dev`. Every dev-side CLI call in a session passes `--profile dev` explicitly; a local variable named `…Token = create…(` also trips the gitleaks `yyt-env-credential` rule — name it `tokenMinter`.
- **Never run `dart format` over `lib`/`test` wholesale** (2026-09-29, `todo/49`): the local Dart 3.13 formatter re-flows ternaries and argument lists differently from the style the tree was committed in, so a blanket run dirtied 40 unrelated files and one hunk inside a file the task did touch. Format only the files you wrote (`dart format <paths>`), and diff a touched file for hunks you did not write before committing.

- A card that calls a route an older console may not have (`LimitsSection` → `GET /limits`, `todo/54`, 2026-09-29) treats that 404 as "unsupported" and shows a hint, never the error notice: the app ships to phones on its own schedule and a stage can run behind it. A widget test that pins a screen's call order (`calls.last`) breaks the moment a card adds a request; filter the calls to the ones the assertion is about instead.
- One `ProjectsApi` per `ProjectScreen`, captured with its server and token and passed to every tab and pushed screen (`rules/security.md`, one profile per request chain). A profile switch pops every route, so nothing outlives the profile it was built for.
- When a console route the app uses changes shape, `lib/projects/*_models.dart`, `projects_api.dart` and the screen change in the same commit; new response fields are read as optional (an older console omits them), and a PATCH sends only the keys the user changed — the server bodies are `.strict()`, so an unchanged key an older console does not know would be a 400.
- Channel config forms mirror `apps/console-web/src/lib/channelForm.ts` (fields, defaults, how the config is **rebuilt**): the server schemas are strict, so echoing a stored config's unknown keys back is not "preserving" them, it is a 400. Auth configs are a partial patch (blank `clientSecret` = omit the key).
- **A wrapper that returns `child` in one state and `Column([banner, Expanded(child)])` in another rebuilds the child** (2026-09-27, `SelfUpdateBanner`): the element type at that slot changes, so Flutter discards the subtree and the child's state — here the app list, whose `initState` starts the list load — restarts every time the banner appears or is dismissed. Keep one tree shape (`Column([if (showing) banner, Expanded(key: …, child: …)])`) and pin it with a test whose child counts its `initState`.
- A launch sends one request at a time: the self-update check waits for the first list load (`HomeShell` hands the banner a `Completer`'s future that `UpdaterApp`'s one-shot `onFirstLoadDone` completes, loaded or failed; the banner caps the wait at 30 s). On Lambda every concurrent request needs a container of its own, and on a quiet stage that is a cold one.
- A `testWidgets` body that calls a platform `MethodChannel` with no mock handler hangs until the per-test timeout: mock the channel to throw `MissingPluginException` (the app's fallback path) or record the call.
- An app release uploads under the **full** pubspec version, `x.y.z+build` (`1.5.6+25`), because that is what every earlier row carries and what the self-update check compares suffix-aware; a bare `1.5.6` went up first on 2026-09-29 and had to be deleted and re-uploaded. The README recipe's "pubspec version" means the whole string.
- The app's publish panel (`lib/listing/`, 2026-09-29) sits **below** the build list: installing is the screen's job and a `members` listing renders up to 100 viewer rows. Viewer refusals the field is about (404 not a member / pending, 409 cap) go under the field and re-read the list; a 401 during the first load must clear `_loading`, because `invalidate` is a no-op when no saved profile holds that token and the panel would spin forever.
- `flutter test`/`analyze` rewrite `pubspec.lock` and `analysis_options.yaml` under a newer SDK (3.47 adds an `analyzer: exclude` block); commit those with the change rather than reverting them every run. A newer SDK also raises the Android toolchain floor (3.47's dependency check refuses the build below Gradle 8.14, AGP 8.11.1 and KGP 2.2.20): when `flutter build apk --release` refuses, bump all three together and prove it with a release build before the upload, not after. Done 2026-09-26 at the floor (Gradle 8.14.3, AGP 8.11.1, KGP 2.2.20; the build now only warns toward 9.1 / 9.0.1 / 2.3.20): KGP 2.2 makes `android { kotlinOptions }` an error (use a top-level `kotlin { compilerOptions { jvmTarget } }`), and the migrator writes `android.builtInKotlin=false` / `android.newDsl=false` into `gradle.properties` on every build — commit them.

## Go CLI (`cli/`)

- A flag that _removes_ an optional config object on update (`--aoi-range 0`) must put an **untyped** `nil` into the `map[string]any` body: a typed nil map (`var m map[string]any; body["aoi"] = m`) does not compare equal to `nil` through the interface, so the merge loop keeps the key and the server sees `{}` or the old object. `channels update` drops nil-valued keys from the fetched config before PATCHing (full replace for every kind but `auth`), and nested objects (`capabilities`, `aoi`) merge one level deep so a single flag does not reset its siblings.

- Shared shapes (dedup pass 2026-09-02, `todo/29`): a resource addressed as `/<base>/{id}` with a name + optional description gets its `get`/`update`/`delete` from `internal/cmd/resource.go` (`newResourceGet/Update/Delete`, generic over the row type — `write` is still the caller's argument); per-channel credentials (`redis-user`, `doc-key`) are one `credentialCmd[T]` spec; presign → PUT → commit is `uploadFile[T]`; a `--body <md|@file>` reader is `readBody`; terminal-escape stripping is `internal/textsafe.Clean`, a leaf package both `api` and `output` import — never make `api` import `output` (a printer that renders `api.Error` would then be a cycle). Golden files are the proof that such a fold changed nothing: never regenerate them (`-update`) during a refactor.
- Every resource command maps 1:1 to a console route; when a route's semantics change (e.g. PATCH partial vs full replace), update the CLI and its `httptest` fake in the same commit. Golden files: `go test ./internal/cmd -update`.
- Context (`internal/cmd/context.go`, 2026-08-26): a command that takes `<channel>`/`<app>`/`<bundle>` gets a `*Resolver` closure and calls it with `write=true` when it mutates — that flag is the only thing separating "auto-select the sole project" from "refuse with the hint", so a new mutating command that passes `false` silently re-introduces the ambiguity trap for scripts. Ids (`IsID`, same prefix list as console's `ID_LIKE`) bypass resolution entirely; keep the two regexes in step when a prefix is added. Tests: `ctxRoutes(...)` adds the team/project/list routes the resolver walks and never overrides a route the test supplied; `withProject(t)` pins `YYT_PROJECT`; `TestMain` unsets `YYT_TEAM`/`YYT_PROJECT`/`YYT_PROFILE` so the developer's own shell cannot leak in.
- Context layering has one non-obvious rule (`contextSpec`): a project from a lower layer than the team is dropped, because ids are stage- and team-specific — a profile's `prj_…` pin combined with `--team other` passed the "explicit" check and would have written into the pinned team. Local resolution failures are `*ContextError` → exit 6; unresolved names are synthesized `api.Error{404}` → exit 5, so scripts can tell "wrong team name" from "app missing, will be created".
- Grouping commands (`catalog`, `team`, `project`, …) are wrapped in `group()`: cobra treats a non-runnable parent's unknown subcommand as "print help, exit 0", which would let a script still calling the removed `catalog group …` pass green.
- Releases are tag-driven (`cli/vX.Y.Z`) via `cli/scripts/build-release.sh` + `gh release create`; goreleaser OSS cannot version from prefixed monorepo tags. `yyt self update` (`internal/selfupdate`), `cli/install.sh` and `cli/install.ps1` depend on that layout — asset name `yyt_<ver>_<os>_<arch>.tar.gz|zip`, `checksums.txt` with `<hex>  <asset>` lines, tag URL-encoded as `cli%2Fv…` — so changing `build-release.sh` means changing `selfupdate` and its `httptest` fake in the same commit. It never reads the config or calls the console; `Updater` fields point tests at a fake GitHub. `Replace` writes a temp file beside the binary, fsyncs, and renames (Windows: rename the running exe to `.old` first). The workflow publishes as a draft and flips it **by release id**, because `Latest` skips drafts and a release object exists before its assets finish uploading. If the tag was pushed by creating the release in the GitHub web UI, that release already exists (published, no assets) and the workflow only uploads into it — `gh release create` would add a second, stranded draft and `gh release edit <tag>` resolves to the published one (v0.4.0, 2026-08-27: assets moved by hand, draft deleted). Both `Latest` and `install.sh` read only the first 100 releases — if another tag family ever gets GitHub releases, filter server-side or page.
- Side effects the console performs on the CLI's behalf (the commit creating and linking a project version) are reported on **stderr** in the same shape as the CLI's own creations (`created version <name> (<id>)`, `linked to version <name> (<id>)`), so stdout goldens and `--json` stay the resource itself; a name the CLI resolves and may create (`ensureVersion`) distinguishes "not in the list" (`missingVersion`, create it) from a 404 on the list route (project gone — surface it, never POST). Test the 409 branch by having the fake's POST plant the winner in the list, not by pre-seeding it — pre-seeding short-circuits at the first lookup and the branch stays untested.
- **The CLI ships for three OSes, and Windows has no permission bits** (2026-09-29): Go reports `0777` for every Windows directory, so the `.yyt.json` world-writable guard ended the search at the first directory and the file was never found there — a guard built on a POSIX bit needs a `runtime.GOOS` gate and a test that skips on Windows (`context_test.go`), and `dir == home` needs `filepath.Clean` + case folding (`sameDir`). Relative paths the CLI builds with `filepath.ToSlash` are matched with `path.Match`, never `filepath.Match` (on Windows `\` is a separator there, so `*` crosses directories). Config and cache live in `os.UserConfigDir`/`os.UserCacheDir`, so docs and help text name all three locations, not `~/.config`. CI's `go` job is an OS matrix (ubuntu/macos/windows) with `shell: bash`; the Windows runner also parses `install.ps1`, and `.gitattributes` pins `eol=lf` because the runner's `autocrlf=true` would turn every golden file into CRLF. **Windows cannot delete an open file**: the first matrix run failed on a `defer os.Remove(tmp.Name())` whose error paths returned before `tmp.Close()` (`asset_crypt.go` encrypted download) — a temp file's cleanup defer closes then removes, and a `Write() != nil || Close() != nil` short-circuit skips the Close on exactly the path that needs it. The test that catches it is the one asserting the directory is empty afterwards (`TestAssetDownloadEncrypted`), so keep such assertions.
- A table column that scripts grep keeps its raw value when a label is added beside it (`project version get`, `todo/52`, 2026-09-29): `TARGET` became the resolved name and the old id string moved to an `ID` column rather than vanishing, and the golden was regenerated on purpose with the diff read line by line — a `-update` during a refactor is the one thing goldens forbid, an intended output change is what it is for. A list filter that resolves a name uses the read-only resolver (`cc.version`), never `ensureVersion`: `issue ls --version 9.9.9` must fail, not create `9.9.9`.

- A command that reads its payload from stdin (`yyt kv entry put`) takes it from `App.In` (nil → `os.Stdin`) so a test can hand in a `strings.Reader`; validate what can be validated locally (`json.Valid`) before resolving the context, so a typo costs no request. A value printed for a pipe (`entry get`) goes out with `fmt.Fprint` and no `textsafe.Clean` — safe only because both writers admit valid JSON and JSON forbids raw U+0000–001F (the class `Clean` strips), so no stored value can carry an escape sequence; a field that is not JSON-validated does not get this exemption. Stripping bytes would corrupt the very thing the command exists to hand over; the table view is where `Clean` belongs (`Printer.Table` cleans every cell).
