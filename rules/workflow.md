# Workflow

## Per-task completion ritual

1. Make the change testable and cover new/changed behavior with vitest (or `go test` for the CLI).
2. Manually verify on the `dev` stage with curl/wscat or `scripts/smoke/*` (see `manual-verification.md`).
3. Run three fresh-context subagents to adversarially review the change (correctness, security, operability).
4. Apply the review feedback.
5. Record reusable lessons in `rules/*.md`; update `rules/index.md` if files changed. Update `todo/index.md` (status table, progress log with absolute date, next work) and tick the area checklist.
6. Commit to `main` with an imperative message and push to `origin` (`git@github.com:yingyeothon/service.git`). No PRs unless branch protection appears.

## Documentation discipline

- `docs/decisions.md` is the contract. If implementation forces a change, edit the doc in the same commit and note it in `todo/index.md`.
- Do not leave work in chat only: anything a future session needs must be in `todo/` or `rules/`.
- A scope qualifier in `docs/` is a deferral, not a policy: "grid bucketing and radius config are explicitly not built **at this scale**" was read as "the gateway will never do AOI", and the review built on that for a whole session before the owner corrected it (2026-09-01, `todo/26`). When a sentence rules something out, say whether it is _not yet_ or _not ever_, and when reading one, check the protocol before trusting the prose — `pos` had carried `(x,y)` from day one, which no relay needs unless it intends to filter by them. The same rule as the seatless-admin case (2026-08-29): a restriction the assistant inferred is not "by design".
- Commit per coherent unit; never `git add .` when generated files are present. Keep `.gitignore` current.
- Sessions start by reading `todo/index.md` → "Next work"; sessions end by updating the same section.
- Retiring a todo doc: fold design into `docs/`, lessons into `rules/`, leave only unchecked items in `todo/`; user-owned tasks (OAuth app registration, email confirmations, private ops-repo work) stay in `todo/` because nothing in this repo can close them. `docs/`/`rules/` are public: operational identifiers go to gitignored `local/ops-notes.md`.
- Review the plan before the code when a change spans schema + services + clients (team/project rework, 2026-08-26): three fresh-context adversarial reviews of the plan document (consistency / security & permissions / operations & migration) found 6 blockers and ~20 majors, all real, before a line was written.
- A phase must be a self-contained commit: when a schema column becomes required later, keep the input type optional in the expand phase — making it required early breaks every stack that bundles the same Prisma client (console, auth, state) in one commit.

## Deduplication passes (`nose`, 2026-09-02)

- `nose query . --exclude 'node_modules/**' --exclude 'dist/**' --exclude 'coverage/**' --exclude '**/*.md' --exclude '**/generated/**' --exclude '**/.serverless/**'` ranks duplicated families; `id=<fam> full` prints the copies with a diff, `group=dir` the concentration. Read every flagged region before acting: roughly a third of the families differ in policy (timeouts, cap semantics, required vs optional fields, the examples' deliberate copies) and folding those would change behaviour or need more parameters than lines saved.
- A dedup refactor is behaviour-preserving only when each call site passes its **current** literal (message, TTL, flag) to the helper — the `git diff` at the call site must show the same string that was there before — and untested production code (handlers, S3 stores, SPA tabs) gets a test pinning today's output _before_ it is refactored.
- `--baseline local/nose-baseline.json --fail-on new` is location-sensitive: any edit that shifts lines re-flags the families below it as "new", so it is not a CI gate here. Track progress by family id from the pre-pass report (`local/nose-before.md`) and re-write the baseline after each commit.
- Copies that have silently drifted (one side gained a guard the other lacks) are findings for the owner, not things a dedup fixes in passing — list them in the todo doc and leave both sides as they are.

## Console SPA (`apps/console-web`)

- `pnpm -r build` now runs `vite build`; `pnpm lint`/`typecheck` cover `.tsx` (type-aware ESLint via `projectService`). SPA tests run under the root `pnpm test` (`vitest.config.ts` projects include `apps/*`) but are excluded from the coverage thresholds on purpose.
- When a console route changes shape, update `src/types.ts` + `src/api.ts` and the affected page in the same commit (same rule as the CLI).
- **Page grammar (2026-09-02, `todo/30`)**: every page is a List, a Detail, the one Form page (`channels/new`) or a Utility page, built from `src/components/{PageHeader,Section,DataTable,FilterBar,ResourceDrawer,RowMenu,EmptyState,ReadOnlyBanner,Loading}.tsx` with `src/lib/notify.ts` and `src/lib/confirm.tsx`. The rules the kit encodes, so a page never invents its own arrangement:
  - The header renders before the data: pass `title={data?.name}` (a skeleton bar while undefined) and put the body behind `data ? … : error ? <Notice/> : <PageSkeleton/>`. Never `return <Spinner/>` above the header — the old pages hid their own title while loading.
  - One filled button per viewport, and it is the header's: the list's `New <noun>` or the detail's one primary verb (`Publish event`, `Put something up`). Section actions (`New project`, `Add member`, `Grant access`, `Run cleanup`) are white `variant="default"` buttons; red outline exists only in the drawer's danger zone. `Edit` is always the first white button on a detail page; destructive verbs go to the overflow menu (`danger: true`) or a `RowMenu`, never a button in the header, and the overflow carries a delete only when the drawer is out of reach (a seatless admin on Team/Project/Channel, a non-author owner on a discussion). Two documented in-row buttons: `Approve` on a pending seat (the row's one fast path) and the `Show files`/`Detail` expanders. A platform admin acting on someone else's show sends a reason on every write (submit, grant, revoke, update, close, delete).
  - Create and edit both open a right `ResourceDrawer` (`useDrawerForm` resets the values on every open); the edit drawer's foot is the `danger` zone. `onSubmit` closes the drawer only when the request returned a row (`useAction.run` is `undefined` on failure; map a 204 to `true`). The channel create form stays a page because it is long, kind-switched, and navigates away carrying the once-shown secret.
  - Destructive actions confirm in a modal via `useConfirm()` whose button repeats the verb (`Delete team`, `Kick alice`, `Revoke token`, `Yes, close it`); a `reason` option adds the required field for an admin acting on someone else's content. The hook runs `modals.closeAll()` on unmount, so no page needs to. The two-click `Confirm` is gone; do not bring it back.
  - Success is a toast (`notify.created/saved/deleted/done`); errors stay inline (`Notice kind="error"` in the drawer or under the section). Never a green `Notice` for success unless it carries data the user must act on (the rotation list after leaving a team).
  - Tables are `DataTable`: scroll container, hairline rows, tabular figures, and the loading/error/empty states inside the table area; the first cell is `NameCell` (an `after` slot keeps badges out of the link's accessible name). Filters are `EnumFilter` (≤4 values segmented, more a native select) and apply on change; the audit log's free-text pair is the only `Apply`.
  - Sections (`Section`, an `h2`) stack with hairlines; no cards inside cards. `PageHeader` renders the page's only `h1`. Read-only standing is one `ReadOnlyBanner` sentence plus an optional detail.
  - Tests: `test/wrap.tsx` mounts the full provider stack with `env="test"` (no transitions, no portals) — drawers and modals are `findByRole("dialog")`, row verbs are `Actions for <name>` → `menuitem` → the same-named button in the dialog. Mantine `Select` still needs raw `fireEvent`. `test/kit.test.tsx` pins the kit; a page test pins labels, columns, hrefs, payloads and gating.
- Every route lives in `src/routes.tsx` with the `NAV_ITEMS` path that guards it; `test/routes.test.tsx` proves each guard resolves, so a new page that forgets its nav item fails in CI rather than on a user's screen. Items that must guard without appearing in the menu use `hidden: true`; the project sub-tree (`…/channels/new` included) is guarded by `/teams`.
- `ModalsProvider` must sit **inside** `QueryClientProvider` and the router: `modals.open` renders its children in the provider's portal, and a modal that queries or navigates crashes otherwise. `Modal` sits at z-index 300 so a confirm opens over a drawer (200).
- `useAction.run` returns `undefined` on error; a call whose success is _also_ `undefined` (a 204) must map success to a sentinel (`?? null`, `return true`) before deciding what to do next, and never read `act.error` inside the same closure — it is the value from the render that created the closure, not the one `run` just set.
- What a page may do follows the caller's standing in the team (`useTeamStanding` → `GET /teams/{id}.role`), not the platform role: a seated platform admin writes like any member, a seatless one only reads (`secret: true` routes answer 403), so "delete team/project" is gated on `owner || standing === "admin"`, never on `me.role`.
- TanStack Query defaults: `staleTime: 0` (lists must refetch after a mutation), `queryClient.clear()` on logout/401 (no cross-account cache), a `queryFn` must never resolve `undefined` (use a `null` sentinel for "hidden/403" cards so the error surfaces instead of hanging), and do not put a status filter into a query key when a transition moves the item between statuses (it flashes a spinner).
- Design tokens live in `apps/console-web/DESIGN.md` and reach Mantine only through `src/theme.ts` (`ink` primary, `link` for anchors and the focus ring, radius by role, shadows zeroed) and the `--yyt-*` variables in `styles.css`. Inter is self-hosted (`@fontsource-variable/inter`) because the CSP's `font-src 'self'` forbids a font CDN; the signature colour surfaces appear in exactly two places (the Home hero, the shown-once secret banner).

## Go CLI (`cli/`)

- A flag that _removes_ an optional config object on update (`--aoi-range 0`) must put an **untyped** `nil` into the `map[string]any` body: a typed nil map (`var m map[string]any; body["aoi"] = m`) does not compare equal to `nil` through the interface, so the merge loop keeps the key and the server sees `{}` or the old object. `channels update` drops nil-valued keys from the fetched config before PATCHing (full replace for every kind but `auth`), and nested objects (`capabilities`, `aoi`) merge one level deep so a single flag does not reset its siblings.

- Shared shapes (dedup pass 2026-09-02, `todo/29`): a resource addressed as `/<base>/{id}` with a name + optional description gets its `get`/`update`/`delete` from `internal/cmd/resource.go` (`newResourceGet/Update/Delete`, generic over the row type — `write` is still the caller's argument); per-channel credentials (`redis-user`, `doc-key`) are one `credentialCmd[T]` spec; presign → PUT → commit is `uploadFile[T]`; a `--body <md|@file>` reader is `readBody`; terminal-escape stripping is `internal/textsafe.Clean`, a leaf package both `api` and `output` import — never make `api` import `output` (a printer that renders `api.Error` would then be a cycle). Golden files are the proof that such a fold changed nothing: never regenerate them (`-update`) during a refactor.
- Every resource command maps 1:1 to a console route; when a route's semantics change (e.g. PATCH partial vs full replace), update the CLI and its `httptest` fake in the same commit. Golden files: `go test ./internal/cmd -update`.
- Context (`internal/cmd/context.go`, 2026-08-26): a command that takes `<channel>`/`<app>`/`<bundle>` gets a `*Resolver` closure and calls it with `write=true` when it mutates — that flag is the only thing separating "auto-select the sole project" from "refuse with the hint", so a new mutating command that passes `false` silently re-introduces the ambiguity trap for scripts. Ids (`IsID`, same prefix list as console's `ID_LIKE`) bypass resolution entirely; keep the two regexes in step when a prefix is added. Tests: `ctxRoutes(...)` adds the team/project/list routes the resolver walks and never overrides a route the test supplied; `withProject(t)` pins `YYT_PROJECT`; `TestMain` unsets `YYT_TEAM`/`YYT_PROJECT`/`YYT_PROFILE` so the developer's own shell cannot leak in.
- Context layering has one non-obvious rule (`contextSpec`): a project from a lower layer than the team is dropped, because ids are stage- and team-specific — a profile's `prj_…` pin combined with `--team other` passed the "explicit" check and would have written into the pinned team. Local resolution failures are `*ContextError` → exit 6; unresolved names are synthesized `api.Error{404}` → exit 5, so scripts can tell "wrong team name" from "app missing, will be created".
- Grouping commands (`catalog`, `team`, `project`, …) are wrapped in `group()`: cobra treats a non-runnable parent's unknown subcommand as "print help, exit 0", which would let a script still calling the removed `catalog group …` pass green.
- Releases are tag-driven (`cli/vX.Y.Z`) via `cli/scripts/build-release.sh` + `gh release create`; goreleaser OSS cannot version from prefixed monorepo tags. `yyt self update` (`internal/selfupdate`) depends on that layout — asset name `yyt_<ver>_<os>_<arch>.tar.gz|zip`, `checksums.txt` with `<hex>  <asset>` lines, tag URL-encoded as `cli%2Fv…` — so changing `build-release.sh` means changing `selfupdate` and its `httptest` fake in the same commit. It never reads the config or calls the console; `Updater` fields point tests at a fake GitHub. `Replace` writes a temp file beside the binary, fsyncs, and renames (Windows: rename the running exe to `.old` first). The workflow publishes as a draft and flips it **by release id**, because `Latest` skips drafts and a release object exists before its assets finish uploading. If the tag was pushed by creating the release in the GitHub web UI, that release already exists (published, no assets) and the workflow only uploads into it — `gh release create` would add a second, stranded draft and `gh release edit <tag>` resolves to the published one (v0.4.0, 2026-08-27: assets moved by hand, draft deleted). Both `Latest` and `install.sh` read only the first 100 releases — if another tag family ever gets GitHub releases, filter server-side or page.
- A local CLI binary can lag the repo (`~/.local/bin/yyt` did not know `--team`): verify with `cd cli && go build -o yyt ./cmd/yyt` and run that binary; reinstall via `install.sh` after the release.

- A per-member rate slot shapes the **client**, not only the tests: three presigns in a row from a browser is a 429 on the second, and each failed attempt leaves a reservation holding a quota slot until it expires. Where a flow needs N writes, give the route one call that does all N (the show screenshot presign takes `{files:[…]}`) rather than asking every client to sleep 550 ms between them (2026-09-01).
- When a decision says "one copyable block" (the tslib prefixes, `docs/decisions.md` _Participant credentials_), the SPA, CLI and API must all present it as one unit; the SPA drifted to per-field copy buttons once (fixed 2026-08-28, `CopyBlock` in `apps/console-web/src/components/ui.tsx`). A test that greps `name=value` lines keeps it honest.
- `scripts/smoke/*.mjs` are not executable — call them with `node`; a `Permission denied` inside a `set -e` chain that continues past it means the smoke never ran, so check for `ALL OK` explicitly.
